Let people and projects be renamed and removed

Items link to a person or a project by name, not by id, so the name is the
identity. That made two things impossible: a typo like "Hom" stranded every item
tagged with it, and a person could never be deleted at all -- there was no
dbDeletePerson and no button anywhere. Both are fixed here.

- renameProject / renamePerson rewrite the name and carry every linked item with
  it, so one correction repairs all the items instead of none. Matching goes
  through sameName(), so "ravi", "  RAVI " and "Ravi" all follow. A case-only
  rename is written through too, since the stored spelling is what shows up in
  search and AI context.
- deletePerson untags the linked items. This is the part that is easy to get
  wrong: renderPeople() infers people from the items that name them, so leaving
  the tag behind would re-create the person on the very next render and make
  Remove look like it had done nothing. The items themselves are kept; the
  confirm dialog says so and counts them.
- dbDeletePerson mirrors dbDeleteProject across all three storage paths.
- Blank names and names already taken are refused without touching anything, and
  cancelling the confirm leaves the record and every tag alone.
- Rename uses prompt() and Remove uses confirm(), matching how the app already
  handles destructive actions, so there is no new dialog machinery to maintain.

Seven behavioural tests run the real functions against a stub world. The delete
test uses the real dbDeletePerson rather than a stub -- a stub that only recorded
the id would have passed while the record stayed put. Deleting the untag line
makes that test fail, so it is not vacuous.

audit.mjs now degrades gracefully when no session exists instead of exiting, and
reports model-backed checks as SKIP rather than letting them pass vacuously.
projects-probe.mjs covers rename and remove alongside the existing checks.
