Fix a crash on any item that has no kind

Found by the browser probe while checking the new rename behaviour, not by the
test suite. renderToday() interpolated item.kind.charAt() directly, so one item
without a kind threw a TypeError and left the whole Today view half-rendered --
while kindColor() and kindIcon() on the line above already tolerated a missing
kind. The inconsistency is the tell: everything else in the app defaults it.

How an item loses its kind: importBackup() validated only item.id, and imported
JSON is user-supplied. A backup edited by hand, or one predating the field, lands
in the store with no kind and breaks the view the next time it renders. It is now
defaulted on import, like itemToRow and the Supabase row builders already do, and
the render no longer dereferences it directly. The kind is also escaped now,
since it reaches innerHTML from that same untrusted import.

Also renames the recent-item label to use the defaulted value so the displayed
kind and the colour/icon can never disagree.
